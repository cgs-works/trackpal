Arquitectura de Componentes del Dashboard

Propuesta de modularidad para eliminar la duplicación de código en las 5 vistas actuales.

A

Enfoque A: Layout Compartido Modular (Recomendado)

Creamos un único componente principal DashboardLayout.vue en components/ que renderiza la barra lateral fija (Sidebar), maneja el estado del Dark Mode, el idioma y la información del usuario logueado. Cada vista individual simplemente se envuelve en este componente, eliminando más de 500 líneas de código duplicado de navegación en los dashboards.

<template>
  <DashboardLayout>
    <!-- Contenido específico de la vista (ej: Subscripciones) -->
    <div class="grid grid-cols-1 md:grid-cols-3 gap-6">...</div>
  </DashboardLayout>
</template>
B

Enfoque B: Layout en Router (Router-View)

Configuramos el router/index.js para tener rutas anidadas bajo un layout común. El layout contiene la barra lateral y renderiza un componente <router-view /> en el centro para las sub-rutas.

Ventajas

  • No es necesario importar el componente de Layout en cada vista

Contras

  • Requiere reestructurar la configuración del router de forma drástica
  • Hace que el paso de props o eventos entre el Layout y la vista activa sea más indirecto

Diagrama del Sistema de Componentes (Enfoque A)

App.vue (Punto de entrada)
└── router-view
    ├── LoginView.vue (Pantalla de acceso libre)
    └── Dashboard views (Rutas protegidas con requiereAuth)
        └── DashboardLayout (Componente de Layout)
            ├── SidebarNav (Navegación + Logo + Perfil)
            ├── ThemeToggle (Toggle Dark/Light en LocalStorage)
            └── <slot /> (Contenido específico de cada rol: Master, Tenant o Cliente)
